# Contributing

Thanks for helping! Bug reports with the Canvas response that confused the server are the most useful thing. Remove names, ids and tokens first.

## Setup

```bash
npm install
npm test          # builds into build-test/ and runs node:test
npm run typecheck
```

Node.js 22.13+ is required (the snapshot store uses the built-in `node:sqlite`).

## Layout

| File | What it does |
|---|---|
| `src/cli.ts` | Entry point; picks stdio or `--http`. |
| `src/config.ts` | Every environment variable, validated with zod. Keep the README table in sync. |
| `src/app.ts` | Wires the client, file reader, snapshot service and MCP server together. |
| `src/canvas.ts` | GET-only Canvas client: pagination, rate limits, retries, safe downloads. |
| `src/links.ts` | Finding file/page links in Canvas HTML; crawling a course. |
| `src/extract.ts` | PDF/DOCX/PPTX/text extraction, worker thread, cache. |
| `src/snapshot.ts` / `src/store.ts` | Snapshots, diffing, change events; SQLite with migrations. |
| `src/tools.ts` / `src/snapshot-tools.ts` | MCP tool definitions. |

## Rules

- **GET only.** Never add code that sends anything but `GET` to Canvas.
- **Tests:** add tests for new behavior. Integration tests use the mock Canvas in `test/mock-canvas.ts`; never commit real course data or tokens.
- **Database:** never edit a released migration in `src/store.ts`; append a new one.
- **Change-log stability:** changing how an entity is normalized changes its hash. Only add new fields when they have a value, and list them in `LATER_FIELDS` (`src/snapshot.ts`), so items stored by older versions don't all look "changed" after an upgrade. A new source of items should set `quiet` on its `KindResult` for the same reason.
- **Tool names** are part of the public interface: renaming one is a breaking change (major version).
- Binary test fixtures are generated by `test/fixtures/make_fixtures.py`.
